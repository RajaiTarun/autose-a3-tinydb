# ADR-009: Tight budgets, timeouts, and issue text treated as untrusted
**Status:** Accepted
**Date:** 2026-11-21

## Context
Runs consume a shared Claude Pro limit; a stuck agent or an endless retry loop must not drain it. Anyone
can write an issue, so issue text may contain prompt injection.

## Decision
- **Turn budgets (max_turns):** Spec 8, Design 12, Implementer 25, Tester 20, Reviewer 15.
- **Retries:** stage 3↔4 at most 2, then back to Design once, then stop; at most 2 review rounds.
- **Timeouts:** 30 min for the build job, 20 for review, 10 for CI.
- **Injection:** issue/comment text is passed to scripts via `env:`, **never** as `${{ }}` inside `run:`;
  prompts place it in an `<untrusted_issue>` block marked as data; agents have no token (ADR-005);
  only collaborators can trigger (ADR-010); nothing is ever merged automatically.
- A stage that fails writes the reason into its artifact, comments on the issue and stops.

## Alternatives considered
- *Very tight (half the budgets, 1 retry):* even less usage, but more early stops.
- *Loose (double, 3 retries):* a higher pass rate, but much heavier usage.

## Consequences
- Positive: worst-case usage per run is bounded and known in advance.
- Negative: harder issues (gzip storage) may run out of turns; that is reported as a result.
