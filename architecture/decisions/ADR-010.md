# ADR-010: Start on a label or /autose from collaborators only; one run per issue at a time
**Status:** Accepted
**Date:** 2026-11-21

## Context
Each run spends the maintainer's Claude limit and writes to the repository, so starting a run must be a
deliberate act by a trusted person. Two runs on one issue would push to the same branch.

## Decision
Start on **`issues: labeled` with label `autose`** or an **`issue_comment` starting with `/autose`**.
A gate job allows only `author_association` OWNER, MEMBER or COLLABORATOR and **ignores bot actors**
(so the workflow cannot trigger itself). `concurrency: autose-issue-<N>` with `cancel-in-progress: false`:
a second run for the same issue waits in the queue; different issues run in parallel.

## Alternatives considered
- *Label only:* a smaller surface, but no way to re-run from a PR comment.
- *Anyone may comment /autose:* any stranger could spend the limit.

## Consequences
- Positive: only trusted people spend the budget; no branch races.
- Negative: an outside contributor cannot start a run themselves; a maintainer must label the issue.

## Amendment (2026-11-24, before any real run)
The assignment's trigger sketch also allows `/autose` on an open PR. A collaborator's comment
starting with **`/autose review`** on a PR now runs **only the Reviewer job** on that PR (no
build stages). This lets a maintainer ask for a fresh independent review, and it is how the
five seeded PRs are reviewed in experiment A. The same gate rules apply (collaborators only,
bots ignored).
