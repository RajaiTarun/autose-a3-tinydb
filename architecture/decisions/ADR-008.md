# ADR-008: Keep the Reviewer independent and make it show evidence
**Status:** Accepted
**Date:** 2026-11-21

## Context
The Reviewer uses Haiku 5.5 like most workers (ADR-006), so independence cannot rely on the model alone. A
reviewer that agrees with everything adds nothing.

## Decision
The Reviewer runs in **its own job** (contents: read, so it cannot push) on a **fresh shallow checkout of the
PR head**, with **its own prompt** and **only** the issue, PR diff and code (ADR-003). It is a different model
from the Implementer. To stop it from approving everything: **(1)** every concern *and every approval* must
cite evidence (file:line or a command it ran); **(2)** it must **run pytest itself**; **(3)** it fills a
**fixed checklist** (meets the issue? edge cases? tests meaningful? breaks ARCHITECTURE.md rules?), with
pass/fail per item. A review without evidence is invalid. The verdict names the stage to go back to (design
or implement).

## Alternatives considered
- *The same agent reviewing its own work:* no independence.
- *Tuning the prompt on the seeded PRs:* would improve scores but turn the measurement into training data; the seeded PRs are kept for measurement only.

## Consequences
- Positive: approvals must be justified; evidence makes false approvals visible.
- Negative: Haiku may still miss subtle bugs; checked against the 5 seeded PRs (experiment A).

## Amendment (2026-11-24, security finding during experiment A)
The Reviewer job ran `review.py` and its prompt from the PR's own checkout, so a PR could rewrite
its Reviewer. It now runs the workflow code from a separate checkout of the default branch and
reviews the PR in `./pr` (decision 5.8). Experiment A also showed the Reviewer is only as good as
the architecture document it checks against: a misleading C3 sentence made both Haiku and Sonnet
approve a C3 violation until it was clarified (decision 5.9).
