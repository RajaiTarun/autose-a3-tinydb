# ADR-007: Stage checks are code wherever possible; the orchestrator decides
**Status:** Accepted
**Date:** 2026-11-21

## Context
A stage must not hand over until its check passes. An LLM grading an LLM is unreliable and costs usage.

## Decision
Checks are **scripts**: AC format (Given/When/Then), design names checked against the code with `ast`,
build = install + compile, tests = every AC has a `test_ac<N>_*` test and `pytest` exits 0, release = PR
open and `ci-tests` green. **One Haiku LLM judge** is used only where code cannot decide: "is each AC
testable?". **orchestrator.py makes the final pass/fail decision**, never the agent that did the work.

## Alternatives considered
- *Code checks only:* the cheapest, but a well-formatted yet untestable AC would pass.
- *An LLM judge for every stage:* richer, but less predictable and more usage.

## Consequences
- Positive: checks are repeatable and cost nothing, and failures have exact reasons.
- Negative: structural checks can be gamed (e.g. a trivial `test_ac1_` test); the Reviewer is the safeguard against that.
