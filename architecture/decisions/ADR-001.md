# ADR-001: Split the work across four worker agents, a release script and a separate reviewer
**Status:** Accepted
**Date:** 2026-11-21

## Context
The six stages differ in what they need: stages 1–2 read and write text, stage 3 edits code, stage 4 writes
tests, stage 5 is mechanical, and stage 6 must be independent. One agent carrying everything accumulates a
long context (costly on a shared Claude Pro limit) and ends up grading its own work.

## Decision
We will use **four LLM worker agents** (Spec, Design, Implementer, Tester), a **plain release script** for
stage 5, and a **separate Reviewer agent** in its own job (ADR-008).

## Alternatives considered
- *One agent for stages 1–4:* the fewest hand-offs, but it writes tests that confirm its own code, and its context keeps growing.
- *Three agents (Planner = spec+design, Builder = implement+test):* fewer prompts, but the Builder still tests its own code.
- *One agent per stage, release included:* release needs no judgement (`git push`, `gh pr create`), so an LLM there only adds cost and risk.

## Consequences
- Positive: each agent has a short, focused prompt and only its own tools; the Tester checks the spec, not the Implementer's intent.
- Negative: more prompts to maintain; information can be lost between agents (mitigated by notes, ADR-003).
- We will know this is wrong if most failures come from lost context between stages rather than wrong code. Tested in experiment B (separate Tester vs Implementer writes its own tests).
